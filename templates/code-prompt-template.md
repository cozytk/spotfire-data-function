# 코드 요청 프롬프트 템플릿 (범용)

생성형 AI에게 코드를 요청할 때 그대로 복사해 쓰는 원본입니다.
언어·도구와 무관하게 동작하도록 만들었습니다 (Spotfire 데이터 함수, Python, SQL, 엑셀, 웹 등).

- 해설과 예시: <https://cozytk.github.io/spotfire-data-function/prompting/04-universal-template/>
- 사용법: 아래 블록을 복사 → `( )` 부분만 채움 → 해당 없는 블록은 삭제
- **`[환경]` 과 `[입출력 계약]` 은 절대 지우지 마세요.** 이 둘이 "붙여 넣으면 도는 코드"를 만듭니다.

---

## 1. 전체 템플릿

```text
[목표]
(한 문장으로. 무엇을 만들고 싶은가)

[환경]
- 언어/버전 : (예: Python 3.9 / Oracle 19c / Excel VBA / TypeScript 5)
- 실행 방식 : (예: 사내 배치 서버 / 도구 안에 붙여 넣어 실행 / 브라우저)
- 사용 가능 : (예: pandas, numpy 만. 추가 설치 불가)
- 제한 사항 : (예: 인터넷 접속 불가 / 외부 API 호출 불가 / 파일 쓰기 불가)

[입출력 계약]
- 입력 : (변수명·타입, 또는 테이블명·시트명·파일 경로)
- 출력 : (결과를 무엇에 담아야 하는가 — 변수/테이블/파일/반환값)
- 금지 : (예: print 로 출력하지 말 것 / 파일로 저장하지 말 것)

[데이터]
- 규모 : (예: 약 100만 행 × 20 컬럼)
- 스키마 :
  컬럼명      타입      예시 값 / 의미
  ID          문자열    'L26043'
  QTY         정수      결측 없음
  MEAS_TIME   문자열    '2026-03-02 06:00:00' (문자열이라 변환 필요)
  VALUE       실수      결측 있음, 0 은 미취득을 의미
- 알려진 문제 : (중복 행 / 정렬 안 됨 / 코드값 표기 흔들림 등)

[요구사항]
1.
2.
3.
(판정 기준은 숫자와 문장으로. "이상치" 대신 "IQR 1.5배 초과")

[제약]
- 사용 금지 : (구식 문법, 느린 방식, 특정 라이브러리)
- 성능 : (예: 100만 행에서 10초 이내, 반복문 대신 벡터 연산)
- 방어 : 입력이 0행일 때, 결측만 있을 때, 0으로 나누기, 컬럼이 없을 때
- 결과가 비어 있으면 (오류 대신 / 안내 1행으로 / 빈 결과 그대로) 처리할 것

[산출물]
- 수정 없이 바로 실행되는 전체 코드 (조각 말고 전부)
- 한국어 주석
- 코드가 무엇을 하는지 3~5줄 요약
- 그 방법을 고른 이유와, 고려했지만 쓰지 않은 대안 1가지
- 결과가 맞는지 확인할 방법 (확인해야 할 숫자·건수)
```

## 2. 짧은 버전 (한 화면짜리 작업)

```text
[환경] (언어/버전), (실행 방식), (사용 가능 패키지)
[입력] (이름 : 타입 / 스키마 한 줄)
[출력] (이름 : 형태)
[요구] 1. … 2. … 3. …
[제약] (금지 사항), 빈 입력·결측·0나누기 방어
[요청] 전체 코드 + 한국어 주석 + 3줄 설명
```

## 3. 환경 블록 스니펫

`[환경]` + `[입출력 계약]` 만 갈아 끼우면 같은 템플릿을 어디서든 씁니다.

### Spotfire Python 데이터 함수

```text
[환경] Spotfire Python 데이터 함수 (번들 인터프리터), pandas/numpy 사용 가능
[입출력 계약]
- 입력 input 은 이미 준비된 pandas DataFrame (파일 읽기 불필요)
- 결과는 output 변수에 DataFrame 으로 할당
- 파일 입출력·print 사용 불가, import 는 스크립트 안에 포함
```

### 일반 Python 스크립트

```text
[환경] Python 3.11, 로컬 실행, 패키지 추가 (가능 / 불가)
[입출력 계약]
- 입력 : ./input/*.csv (UTF-8, 헤더 있음)
- 출력 : ./output/result.xlsx (시트명 'summary')
- 실행 : python run.py --date 2026-03-02 형태의 CLI 인자 지원
```

### SQL

```text
[환경] Oracle 19c (또는 PostgreSQL 15 / MS SQL 2019 / BigQuery)
[입출력 계약]
- 입력 테이블 : FAB_MEAS(약 1억 행, MEAS_TIME 파티션), LOT_MASTER(1만 행)
- 출력 : SELECT 문 하나로 결과 반환 (임시 테이블 생성 권한 없음)
- 제약 : 윈도우 함수·CTE 사용 가능, 힌트는 쓰지 말 것
```

### 엑셀 (VBA / 수식)

```text
[환경] Excel 365, VBA 사용 가능 / 또는 수식만 사용
[입출력 계약]
- 입력 : 'RAW' 시트 A1 부터 헤더 포함, 행 수는 매번 달라짐
- 출력 : 'SUMMARY' 시트 A1 부터 결과 표 작성 (기존 내용은 지우고 다시 쓰기)
- 제약 : 외부 참조·추가 설치 없이 동작해야 함
```

### 웹/프론트엔드

```text
[환경] TypeScript 5, React 18, 사내 디자인 시스템만 사용 (외부 UI 라이브러리 추가 불가)
[입출력 계약]
- 입력 : props 로 data: Row[] 를 받음 (Row 타입 정의는 아래 참조)
- 출력 : 단일 컴포넌트를 export default
- 제약 : 상태 관리 라이브러리 추가 금지, 컴포넌트 안에서 fetch 호출 금지
```

## 4. 상황별 변형

### 기존 코드 수정

```text
[목표] 아래 코드에 (기능)을 추가하고 싶다.

[현재 코드]
(전체 코드. 일부만 붙이면 나머지를 지어냅니다)

[현재 동작] (지금은 무엇을 하고 있는지)
[바꿀 점] 1. … 2. …
[유지할 점] (건드리면 안 되는 부분·출력 형식·함수 시그니처)

[요청]
- 바뀐 부분만이 아니라 전체 코드를 다시 주세요
- 무엇을 왜 바꿨는지 변경 요약을 함께 주세요
```

### 오류 해결

```text
[상황] 아래 코드를 실행하면 오류가 납니다.

[오류 메시지]
(전문을 그대로. 마지막 줄만이 아니라 트레이스백 전체)

[코드]
(전체 코드)

[환경] (언어/버전, 라이브러리 버전, 실행 위치)
[데이터] (행 수, 컬럼, 관련 컬럼의 실제 값 예시 2~3개)
[시도한 것] (이미 해 본 것 — 같은 답을 다시 받지 않기 위해)

[요청]
1. 원인을 한 문장으로
2. 수정한 전체 코드
3. 같은 실수를 반복하지 않으려면 무엇을 알아야 하는지
```

### 코드 이해

```text
아래 코드를 한 줄씩 설명해줘. 나는 (파이썬 초급 / SQL 은 아는데 pandas 는 처음) 수준이야.
1. 전체가 무엇을 하는 코드인지 3줄 요약
2. 블록별로 무엇을 하는지
3. 이 코드가 조용히 틀릴 수 있는 상황이 있다면 어디인지
4. 값을 바꿔 가며 실험해 볼 만한 부분은 어디인지
```

### 검토 요청

```text
아래 코드가 의도대로 동작하는지 검토해줘.
[의도] (무엇을 하려는 코드인지)

(코드)

특히 아래 관점으로 봐줘:
1. 결측·빈 입력·중복이 있을 때 결과가 왜곡되는 지점
2. 0으로 나누기, 인덱스 범위, 타입 변환에서 깨질 수 있는 지점
3. 정렬이 필요한데 빠진 곳
4. 데이터가 100배 커졌을 때 느려질 지점
5. 처음 보는 사람이 오해할 만한 부분

문제가 없으면 '없음'이라고 말해줘. 있는 것처럼 지어내지 마.
```

### 성능 개선

```text
아래 코드가 (데이터 규모)에서 (현재 소요 시간) 걸립니다. (목표 시간) 이내로 줄이고 싶습니다.

(코드)

[조건] 결과는 완전히 동일해야 함 / 사용 가능한 것은 (라이브러리·메모리 한도)
[요청]
1. 병목이 어디인지, 왜 느린지
2. 개선한 전체 코드
3. 예상 개선 폭과, 결과가 같은지 확인하는 방법
```

### 다른 언어·도구로 이관

```text
아래 (SQL / VBA / R) 코드를 (Python pandas) 로 옮겨줘.

[원본 코드]
(코드)

[옮길 환경] (환경 블록)
[요청]
- 동작이 완전히 같아야 함. 다르게 동작할 수밖에 없는 부분이 있으면 먼저 알려줘
- 원본의 각 부분이 새 코드의 어디에 해당하는지 대응표
- 두 결과가 같은지 확인하는 방법
```

## 5. 이어서 요청할 때 쓰는 문장

| 목적 | 문장 |
|---|---|
| 누락 확인 | 요구사항 1~5번이 각각 코드의 어디에 구현됐는지 짚어줘. |
| 가정 드러내기 | 이 코드가 암묵적으로 가정하고 있는 것을 전부 나열해줘. |
| 예외 보강 | 실제 운영에서 이 코드가 죽을 수 있는 상황 5가지와 각각의 방어 코드를 알려줘. |
| 대안 비교 | 다른 접근 2~3가지를 장단점과 함께 비교하고, 이 상황에는 무엇을 권하는지 말해줘. |
| 단순화 | 동작은 같게 유지하면서 더 짧고 읽기 쉽게 다시 써줘. |
| 검증 | 이 코드가 맞는지 확인할 수 있는 테스트용 입력과 기대 결과를 만들어줘. |
| 인수인계 | 이 코드를 처음 보는 동료에게 설명할 문서를 5줄로 써줘. |

한 번에 요구사항 10개를 던지지 말고 **3~4개씩 쌓으세요.** 누락도 적고 검증도 쉽습니다.

## 6. 보내기 전 최종 점검

- [ ] 환경(언어·버전·실행 방식·사용 가능 패키지)을 적었는가
- [ ] 입력이 어디서 오는지, 결과를 어디에 담는지 적었는가
- [ ] 컬럼명·타입·예시 값을 붙였는가
- [ ] 요구사항에 번호를 매겼는가
- [ ] 애매한 표현을 숫자와 기준으로 바꿨는가 ("최근" → "최근 7일")
- [ ] 하지 말아야 할 것(금지 사항)을 적었는가
- [ ] 빈 입력·결측·0으로 나누기 방어를 요구했는가
- [ ] 전체 코드와 설명, 검증 방법을 요구했는가
- [ ] 보안상 문제가 되는 실제 데이터를 붙이지 않았는가

> **사내 데이터를 외부 AI 서비스에 붙여 넣기 전에 반드시 보안 정책을 확인하세요.**
> 대부분은 컬럼명과 타입만으로 충분하고, 값이 필요하면 형식만 같은 가짜 예시 값
> (`'L26043'`, `520.1`)으로 바꾸면 됩니다.
