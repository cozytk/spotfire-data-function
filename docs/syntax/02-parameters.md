## 파라미터 타입 3가지

| 타입 | Python에서의 모습 | 언제 쓰나 |
|---|---|---|
| **Value** | `str`, `int`, `float`, `bool` | 임계값, 기간, 컬럼명 등 **설정값 1개** |
| **Column** | `pandas.Series` | 컬럼 **몇 개**를 개별적으로 다룰 때 |
| **Table** | `pandas.DataFrame` | 테이블 전체 또는 여러 컬럼 (**가장 많이 씀**) |

### 언제 Column이고 언제 Table인가

- 대상 컬럼이 **적고 고정적**이거나, **서로 다른 테이블의 컬럼**을 모아야 한다 → `Column` 여러 개
- 대상 컬럼이 **많거나 그때그때 달라진다** → `Table` 하나

실무에서는 **대부분 Table 하나**로 받고 스크립트 안에서 컬럼을 고르는 편이 관리하기 편합니다.

```python
# Column 입력 3개를 받은 경우 (각각 Series)
df = pd.DataFrame({"두께": thickness, "온도": temp, "압력": pressure})

# Table 입력 1개를 받은 경우 (이미 DataFrame)
df = input[["THICKNESS", "TEMP", "PRESSURE"]]
```

## 입력을 어디에 연결하는가

데이터 함수를 **실행**할 때 각 입력 파라미터를 무엇에 연결할지 지정합니다.

| 연결 대상 | 설명 |
|---|---|
| **데이터 테이블 / 컬럼** | 가장 일반적. 테이블 전체 또는 선택한 컬럼들 |
| **표현식(Expression)** | 계산식 결과를 입력으로. 여러 컬럼은 쉼표로 구분 |
| **문서 속성 (Document Property)** | Value 입력에 연결. 텍스트 영역 컨트롤과 연동 |
| **컬럼 속성 / 데이터 테이블 속성** | 메타데이터를 값으로 전달 |

### 표현식으로 입력 넣기

입력 소스를 컬럼이 아니라 **표현식**으로 지정할 수 있습니다.
Spotfire 표현식 언어를 그대로 쓸 수 있어서, 간단한 전처리는 여기서 끝낼 수 있습니다.

```text
[THICKNESS] - [SPEC_CENTER]           단일 계산 컬럼을 입력으로
[THICKNESS], [CD], [TEMP]             여러 컬럼을 한 번에 (쉼표 구분)
Concatenate([LOT_ID], "-", [WAFER])   조합 키를 만들어 전달
```

{: .팁 }
> 표현식으로 미리 계산해서 넘기면 Python 코드가 짧아집니다.
> 다만 **로직이 두 군데로 흩어지는** 단점이 있습니다.
> 나중에 "이 값 어디서 계산된 거지?"를 겪지 않으려면,
> **간단한 것만 표현식으로** 하고 복잡한 로직은 Python에 모으세요.

## 입력 제한 (Limit by) — 마킹과 필터링

**여기가 가장 중요한 부분입니다.**
Table/Column 입력에는 "어떤 행을 넘길지" 제한을 걸 수 있습니다.

| 제한 | 전달되는 행 |
|---|---|
| 제한 없음 | 데이터 테이블 **전체** |
| **필터링(Filtering)** | 현재 필터 조건에 맞는 행만 |
| **마킹(Marking)** | 사용자가 차트에서 **선택(마킹)한 행만** |
| 둘 다 지정 | **교집합** (필터도 통과하고 마킹도 된 행) |

### 왜 이것이 강력한가

**사용자의 화면 조작이 곧 함수의 입력**이 되기 때문입니다.

```text
사용자가 관리도에서 이상 구간을 드래그
        ↓  (마킹 변경)
데이터 함수 자동 재실행
        ↓
"선택한 구간은 CHAMBER=B 비중이 3배 높습니다" 라는 결과가 즉시 표시
```

이것을 구현한 것이 [21번 예제](../../examples/21-marking-compare/)입니다.
같은 테이블을 **제한이 다른 두 입력**으로 받는 것이 핵심 아이디어입니다.

| 파라미터 | 타입 | 제한 |
|---|---|---|
| `input_marked` | Table | 마킹으로 제한 |
| `input_all` | Table | 제한 없음 |

{: .주의 }
> **아무것도 마킹하지 않으면 0행이 들어옵니다.**
> 마킹 기반 데이터 함수 오류의 대부분이 이 상황입니다. 코드 맨 앞에서 반드시 확인하세요.
>
> ```python
> if len(input_marked) == 0:
>     output = pd.DataFrame([{"안내": "차트에서 데이터를 선택하세요"}])
> else:
>     ...
> ```

### 자동 재계산 설정

마킹·필터 연동을 살리려면 데이터 함수 속성에서
**"입력이 변경되면 자동으로 다시 계산"** 을 켜야 합니다. 켜지 않으면 수동 새로 고침이 필요합니다.

## 출력 파라미터

출력 변수의 **Python 타입**에 따라 Spotfire에서 받을 수 있는 형태가 정해집니다.

| Python 타입 | Spotfire 출력 |
|---|---|
| `pandas.DataFrame` | **데이터 테이블** (새로 만들거나 기존 테이블 교체) |
| `pandas.Series` | 기존 테이블에 **컬럼 추가** |
| `str`, `int`, `float`, `bool` | **문서 속성** (단일 값) |
| 그림 객체 (matplotlib Figure 등) | 문서 속성 (**Binary**) → 텍스트 영역에 이미지로 표시 |

### 출력 연결 방식 3가지

1. **새 데이터 테이블 생성** — 가장 안전. 원본은 그대로 두고 결과를 새 테이블로
2. **기존 데이터 테이블 교체** — 반복 실행 시 테이블이 늘어나지 않음
3. **기존 테이블에 컬럼 추가** — 행 수와 **순서가 정확히 같아야** 함

{: .주의 }
> **"컬럼 추가"로 출력할 때는 행 수와 순서가 반드시 보존되어야 합니다.**
> 스크립트에서 `dropna()`나 `sort_values()`를 했다면 원본과 어긋나 **엉뚱한 행에 값이 붙습니다.**
> 정렬이나 행 삭제가 있었다면 **키 컬럼을 포함한 새 테이블로 출력하고 조인**하세요.

## 파라미터 설계 체크리스트

데이터 함수를 만들기 전에 이 표를 먼저 채우면 실수가 크게 줍니다.

| 항목 | 정할 것 |
|---|---|
| 입력 개수/이름 | 스크립트 변수명과 동일하게 |
| 각 입력의 타입 | Value / Column / Table |
| 각 입력의 제한 | 없음 / 필터링 / 마킹 |
| 바뀔 수 있는 설정값 | → **Value 입력 + 문서 속성**으로 뺀다 |
| 출력 개수/이름 | 결과 테이블마다 하나씩 |
| 출력 연결 방식 | 새 테이블 / 교체 / 컬럼 추가 |
| 빈 입력일 때 동작 | 0행이 들어와도 죽지 않는가 |

---

## 정리

- 파라미터 타입은 **Value / Column / Table** 3가지
- 입력은 **테이블·표현식·문서 속성**에 연결할 수 있다
- **마킹/필터링 제한**이 Spotfire 데이터 함수의 가장 강력한 무기
- 마킹 입력은 **0행이 들어올 수 있다** — 반드시 방어
- "컬럼 추가" 출력은 **행 수와 순서가 보존될 때만** 사용
