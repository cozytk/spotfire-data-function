## 환경·설치

### Python을 따로 설치해야 하나요?

**아니요.** Spotfire Analyst에는 Python 인터프리터가 **번들**되어 있습니다.
설치 폴더의 `Modules` 아래에 있으며, `pandas`, `numpy` 등 기본 패키지가 함께 들어 있습니다.
이 교안 예제의 대부분은 추가 설치 없이 동작합니다.

회사 표준 Python 환경을 쓰고 싶다면 `도구 > 옵션 > 데이터 함수` 에서 경로를 지정할 수 있지만,
**그 환경에 필요한 패키지가 모두 설치되어 있어야** 합니다. 특별한 이유가 없다면 번들 인터프리터를 쓰세요.

### 패키지는 어떻게 설치하나요?

`도구 > Python 도구 > 패키지 관리` 에서 이름으로 검색해 설치합니다 (내부적으로 pip 사용).
사내망에서 외부 접속이 막혀 있으면 실패할 수 있으며, 이 경우 IT 담당 부서에 문의하세요.
조직 전체 배포는 관리자가 **`.spk` 패키지**로 묶어 배포할 수 있습니다.

### `scipy`나 `scikit-learn` 설치가 안 됩니다

두 가지 방법이 있습니다.

1. AI에게 **"numpy만으로 구현해줘"** 라고 요청 — 선형회귀·KMeans·이동통계 정도는 충분히 가능합니다.
2. 해당 예제를 건너뛰기 — 이 교안에서 추가 패키지가 필요한 것은 3개(18·22·23번)뿐입니다.

### R 데이터 함수와 Python 중 무엇을 쓰나요?

새로 배운다면 **Python을 권장**합니다.
사내외 자료·예제·AI의 코드 생성 품질 모두 Python 쪽이 압도적으로 많습니다.
기존에 R 자산이 있다면 굳이 옮길 필요는 없습니다.

### IronPython 스크립트와 뭐가 다른가요?

**완전히 다른 것입니다.** 혼동이 아주 흔합니다.

| | Python 데이터 함수 | IronPython 스크립트 |
|---|---|---|
| 목적 | **데이터 처리·분석** | **UI 제어·자동화** |
| 다루는 것 | pandas DataFrame | Spotfire 객체 (시각화, 필터, 페이지) |
| 예시 | 중복 제거, 통계 계산 | 버튼 클릭 시 페이지 이동, 필터 초기화 |
| 사용 패키지 | pandas, numpy 등 | Spotfire API |

"차트 색을 바꾸고 싶다" → IronPython
"데이터를 가공하고 싶다" → **데이터 함수**

## 입력·출력

### 입력 테이블이 비어 있으면 어떻게 되나요?

0행짜리 DataFrame이 전달되고, 이후 계산에서 오류가 나기 쉽습니다.
**특히 마킹으로 제한한 입력**은 사용자가 아무것도 선택하지 않으면 항상 0행입니다.

```python
if len(input) == 0:
    output = pd.DataFrame([{"NOTE": "데이터를 선택하세요"}])
else:
    ...
```

### 결과가 빈 테이블이면 오류가 납니다

```text
SBDFError: cannot determine type for column 'X'; all values are missing
```

Spotfire는 컬럼의 **값을 보고** 타입을 정하므로, 모든 값이 결측이면 실패합니다.
빈 결과일 때는 **타입에 맞는 기본값이 든 1행**을 대신 반환하세요.
([04번 예제](../../examples/04-join-and-split/)의 `safe()` 함수)

값이 없는 컬럼을 꼭 내보내야 한다면 **타입을 직접 지정**하면 됩니다.

```python
import spotfire
spotfire.set_spotfire_types(result, {"REMARK": "String"})   # 모든 가공을 끝낸 뒤 마지막에
```

한 번에 방어하려면 [26번 예제(출력 안전장치)](../../examples/26-safe-output/)의
`finalize()` 를 복사해서 쓰세요.

### 출력 테이블이 실행할 때마다 새로 생깁니다

출력 파라미터 연결에서 **"새 데이터 테이블 생성"** 대신
**"기존 데이터 테이블 교체(Replace)"** 를 선택하세요.

### 기존 테이블에 컬럼만 추가하고 싶습니다

출력 연결에서 "데이터 테이블에 열 추가"를 선택합니다.
단 **행 수와 순서가 원본과 정확히 같아야** 합니다.
스크립트에서 `dropna()`나 `sort_values()` 를 했다면 엉뚱한 행에 값이 붙습니다.
정렬·삭제가 있었다면 **키 컬럼을 포함한 새 테이블로 출력하고 조인**하세요.

### 출력을 문서 속성으로 받으려면?

출력 변수에 **단일 값**(`str`, `int`, `float`, `bool`)을 할당하고,
출력 파라미터 타입을 `Value` 로 지정한 뒤 문서 속성에 연결합니다.

```python
output_count = int(len(df))              # 문서 속성(Integer)
output_msg = f"처리 완료: {len(df):,}행"   # 문서 속성(String)
```

텍스트 영역에 `${output_msg}` 로 표시하면 실행 결과를 화면에 보여 줄 수 있습니다.

### 그래프(이미지)를 출력할 수 있나요?

가능합니다. 출력 타입을 `Value` / Spotfire 데이터 타입 **Binary** 로 지정하고 문서 속성에 연결한 뒤,
텍스트 영역에서 "문서 속성의 이미지"로 표시합니다. ([23번 예제](../../examples/23-matplotlib-image/))

다만 이미지는 **데이터가 아니어서** 필터·마킹과 연동되지 않습니다.
Spotfire 기본 시각화로 그릴 수 있는 것은 Spotfire로 그리세요.

## 코드 작성

### `print()` 결과는 어디서 보나요?

**`도구 > 옵션 > 데이터 함수` 에서 데이터 함수 디버깅을 켜면** 실행 결과에
`Standard output:` 아래로 표시됩니다. 오류가 났을 때는 설정과 관계없이 오류 메시지와 함께 나옵니다.

켜지 않으면 성공한 실행의 `print()` 는 보이지 않습니다.
"print를 넣었는데 아무것도 안 나온다"의 원인은 대부분 이것입니다.
([디버깅 방법](../../syntax/06-run-debug/))

### `.dt` 를 쓰면 `AttributeError` 가 납니다

Spotfire의 DateTime 컬럼은 `datetime64[ns]` 가 아니라 **`object` dtype** 으로 들어옵니다.
`pd.to_datetime()` 으로 변환한 뒤에 쓰세요.

```python
df["MEAS_TIME"] = pd.to_datetime(df["MEAS_TIME"])
df["HOUR"] = df["MEAS_TIME"].dt.hour
```

Date·Time·TimeSpan·Boolean·Binary·Currency도 모두 `object` 입니다.
([타입 매핑](../../syntax/03-datatypes/))

### 결과에서 그룹 컬럼이 사라졌습니다

**인덱스는 Spotfire로 전달되지 않습니다.**
`groupby()` 결과를 그대로 내보내면 그룹 키가 인덱스에 있어 조용히 사라집니다.

```python
output = df.groupby("EQP_ID", as_index=False)["THICKNESS"].mean()   # ✅
```

### `inplace=True` 를 썼는데 값이 안 바뀝니다

최신 pandas에서 연쇄 할당은 원본을 바꾸지 않습니다. 재할당 형태로 바꾸세요.

```python
df["X"] = df["X"].fillna(0)      # ✅
df = df.fillna({"X": 0})         # ✅
```

### 한글 컬럼명을 써도 되나요?

동작은 합니다. 다만 아래 이유로 **영문 컬럼명을 권장**합니다.

- 인코딩 문제가 생길 여지가 있고,
- 코드에서 `df["설비ID"]` 처럼 쓰면 오타를 찾기 어렵고,
- AI에게 프롬프트를 줄 때도 영문 쪽이 안정적입니다.

표시용 한글 이름은 Spotfire 쪽에서 컬럼 표시 이름으로 바꾸는 편이 낫습니다.

### 날짜 컬럼이 숫자로 보입니다

문자열로 들어온 시각을 변환하지 않았거나, Excel의 일련번호 형식일 수 있습니다.

```python
df["T"] = pd.to_datetime(df["T"], errors="coerce")                    # 일반
df["T"] = pd.to_datetime(df["T"], unit="D", origin="1899-12-30")      # Excel 일련번호
```

### 정수 컬럼이 1.0, 2.0 처럼 보입니다

해당 컬럼에 **결측이 있어서** Spotfire 쪽에서 이미 Real(실수)로 넘어온 것입니다.
결측을 채운 뒤 `astype(int)`, 또는 결측을 유지하려면 `astype("Int64")` (대문자 I).

### 정수 컬럼에서 `np.isnan()` 이 결측을 못 찾습니다

**오류가 나지 않고 조용히 틀리기 때문에 특히 위험합니다.**

Spotfire의 Integer/LongInteger는 **nullable `Int32`/`Int64`** 로 들어오고,
결측은 `np.nan` 이 아니라 `pd.NA` 입니다.
`np.isnan()` 은 그 자리에 `True` 가 아니라 **`pd.NA` 를 돌려주고**,
`pd.NA` 는 필터링에서 `False` 처럼 취급됩니다.

```python
mask = np.isnan(df["WAFER_NO"])   # 결측 자리에 True 가 아니라 <NA>
mask.any()                        # ❌ 결측이 있는데도 False
df[mask]                          # ❌ 빈 결과

df["WAFER_NO"].isna()             # ✅ 항상 이것을 쓰세요
```

또한 `np.polyfit()` 같은 numpy 함수에 `pd.NA` 가 든 컬럼을 그대로 넘기면
`LinAlgError` 처럼 원인을 짐작하기 어려운 오류가 납니다.
**외부 라이브러리에 넘기기 전에는 일반 실수로 바꾸세요.**

```python
X = df[["THICKNESS", "PARTICLE_CNT"]].astype(float).to_numpy()
```

## 성능·운영

### 데이터 함수가 너무 느립니다

확인 순서:

1. `apply(axis=1)` 이 있는가 → `np.select` / `np.where` 로 교체 (수십 배 차이)
2. 필요 없는 컬럼까지 입력으로 넘기는가 → 입력에서 컬럼 선택
3. 전체 행이 필요한가 → 입력을 **필터링으로 제한**
4. 자동 재계산이 켜져 있는가 → 무거운 함수는 끄고 버튼 실행
5. 출력 테이블이 지나치게 큰가 → 원본 대신 **집계 결과만** 반환

### 몇 행까지 처리할 수 있나요?

명확한 한계는 없지만, 데이터를 Python으로 옮기고 돌려받는 **전송 시간**이 포함됩니다.
수십만 행 × 수십 컬럼을 통째로 주고받으면 계산이 빨라도 느려집니다.
**입력을 최소로, 출력도 최소로**가 원칙입니다.

### Web Player(서버)에서도 동작하나요?

동작합니다. 다만 확인할 것이 있습니다.

- 서버의 Python 서비스에도 **같은 패키지**가 설치되어 있어야 합니다.
- **로컬 파일 경로·네트워크 드라이브 접근 코드는 반드시 제거**하세요. 서버에는 그 경로가 없습니다.
- 여러 사용자가 동시에 실행하면 서버 부하가 커집니다.

### 여러 데이터 함수의 실행 순서를 정할 수 있나요?

명시적인 순서 지정 기능은 없습니다.
A의 출력을 B의 입력으로 연결하면 **의존 관계에 따라 순서가 결정**됩니다.
순서가 중요하다면 아예 **하나의 데이터 함수로 합치는 것**이 가장 확실합니다.

### 다른 분석에서도 같은 함수를 쓰고 싶습니다

**라이브러리에 저장**하세요. 저장된 데이터 함수는 다른 분석에서 불러 쓸 수 있습니다.
이때 컬럼명을 하드코딩하지 말고 [Value 입력으로 파라미터화](../../examples/20-parameterize/)하면
진짜 재사용 가능한 자산이 됩니다.

## AI 활용

### AI가 준 코드가 Spotfire에서 안 돌아갑니다

대부분 아래 다섯입니다. **1~3번은 형태 문제, 4~5번은 타입 문제**입니다.

1. `pd.read_csv(...)` 로 **파일을 읽으려 함** → 입력 변수를 쓰도록 수정
2. `df.to_csv(...)` 로 **파일에 저장** → 출력 변수에 할당하도록 수정
3. **`output` 변수 할당 누락** → 마지막 줄 확인
4. **시각 컬럼에 `.dt` 를 바로 사용** → Spotfire DateTime은 `object` 이므로
   `pd.to_datetime()` 이 먼저 필요 (AI가 가장 자주 하는 실수)
5. **`groupby()` 결과를 그대로 출력** → 인덱스가 전달되지 않아 그룹 키가 사라짐

프롬프트 맨 앞에 [공통 규약 문단](../../prompting/01-tips/)을
붙여 두면 대부분 예방됩니다. ([AI 활용법](../../prompting/))

### 사내 데이터를 AI에 붙여 넣어도 되나요?

**반드시 사내 보안 정책을 먼저 확인하세요.**
대부분의 경우 **컬럼명과 타입만으로 충분**하며, 값이 필요하면 형식만 같은
가짜 예시 값으로 대체하면 됩니다. 이 교안의 데이터도 모두 가상 데이터입니다.

### AI 코드를 그대로 믿어도 되나요?

**아니요.** 오류가 나는 코드보다 **오류 없이 조용히 틀리는 코드**가 훨씬 위험합니다.
정렬 누락, 그룹 경계 침범, 0으로 나누기, 결측 처리 누락이 대표적입니다.
[결과 검증하기](../../prompting/03-verify/)의 4단계 검증을 항상 수행하세요.
