## 왜 하나의 템플릿으로 되는가

AI가 잘못된 코드를 주는 이유는 대부분 **모델이 부족해서가 아니라, 우리가 말하지 않아서**입니다.
말하지 않으면 AI는 가장 흔한 경우를 가정합니다.

| 말하지 않으면 AI가 가정하는 것 | 실제 현실 |
|---|---|
| 데이터를 파일에서 읽는다 | 이미 변수/테이블/시트에 들어 있다 |
| 결과를 화면에 출력한다 | 특정 변수·시트·테이블로 돌려줘야 한다 |
| 최신 라이브러리를 마음껏 쓴다 | 설치할 수 없는 폐쇄망이다 |
| 데이터는 깨끗하다 | 결측·0·중복·타입 불일치가 있다 |
| 데이터는 몇백 행이다 | 100만 행이다 |

이 다섯 가지는 **언어와 도구가 바뀌어도 똑같이 반복**됩니다.
그래서 아래 7개 블록만 채우면 어떤 환경에서도 통합니다.

| 블록 | 무엇을 쓰나 | 빠뜨리면 생기는 일 |
|---|---|---|
| **① 목표** | 한 문장으로 "무엇을 만들고 싶은가" | 엉뚱한 방향의 코드 |
| **② 환경** | 언어·버전·실행 방식·사용 가능 패키지 | 설치 불가 라이브러리, 실행 안 되는 코드 |
| **③ 입출력 계약** | 입력이 어디서 오고 결과를 어디에 담는가 | 결과를 못 받아옴 |
| **④ 데이터·현황** | 스키마, 예시 값, 규모, 지저분한 지점 | 없는 컬럼명을 지어냄 |
| **⑤ 요구사항** | 번호 매긴 처리 단계와 판정 기준 | 일부 누락, 제멋대로 해석 |
| **⑥ 제약·예외** | 금지 사항, 방어해야 할 상황 | 운영 중에 죽는 코드 |
| **⑦ 산출물 형태** | 코드 형태, 주석, 설명, 검증 방법 | 이해 못 하는 코드를 떠안음 |

{: .팁 }
> 순서를 외울 필요는 없습니다. **"무엇을 · 어디서 · 뭘 받아 뭘 내놓고 · 데이터는 이렇고 · 이렇게 처리하고 · 이건 하지 말고 · 이렇게 달라"** 한 줄로 기억하세요.

## 전체 템플릿 (복사해서 사용)

````text
[목표]
(한 문장으로. 예: 설비 알람 로그에서 반복 알람을 찾아 일별로 집계하고 싶다)

[환경]
- 언어/버전 : (예: Python 3.9 / SQL - Oracle 19c / Excel VBA / JavaScript ES2020)
- 실행 방식 : (예: 사내 서버에서 배치 실행 / 도구 안에 붙여 넣어 실행 / 브라우저)
- 사용 가능 : (예: pandas, numpy 만. 설치 불가 — 표준 라이브러리 외 추가 금지)
- 제한 사항 : (예: 인터넷 접속 불가 / 외부 API 호출 불가 / 파일 쓰기 불가)

[입출력 계약]
- 입력 : (변수명·타입, 또는 테이블명·시트명·파일 경로)
- 출력 : (결과를 무엇에 담아야 하는가. 변수/테이블/파일/반환값)
- 금지 : (예: print 로 출력하지 말 것 / 파일로 저장하지 말 것)

[데이터]
- 규모 : (예: 약 100만 행 × 20 컬럼)
- 스키마 :
  컬럼명      타입      예시 값 / 의미
  ID          문자열    'L26043'
  QTY         정수      결측 없음
  MEAS_TIME   문자열    '2026-03-02 06:00:00' (문자열이라 변환 필요)
  VALUE       실수      결측 있음, 0 은 미취득을 의미
- 알려진 문제 : (중복 행 있음 / 정렬 안 되어 있음 / 코드값 표기 흔들림 등)

[요구사항]
1.
2.
3.
(판정 기준은 반드시 숫자와 문장으로. "이상치" 대신 "IQR 1.5배 초과")

[제약]
- 사용 금지 : (구식 문법, 느린 방식, 특정 라이브러리)
- 성능 : (예: 100만 행에서 10초 이내, 반복문 대신 벡터 연산)
- 방어 : 입력이 0행일 때, 결측만 있을 때, 0으로 나누기, 컬럼이 없을 때
- 결과가 비어 있으면 (오류 대신 / 안내 1행으로 / 빈 결과 그대로) 처리할 것

[산출물]
- 수정 없이 바로 실행되는 전체 코드 (조각 말고 전부)
- 한국어 주석
- 코드가 무엇을 하는지 3~5줄 요약
- 그 방법을 고른 이유와, 고려했지만 쓰지 않은 대안 1가지
- 결과가 맞는지 확인할 방법 (확인해야 할 숫자·건수)
````

{: .팁 }
> **전부 채울 필요는 없습니다.** 해당 없는 블록은 지우세요.
> 대신 **② 환경과 ③ 입출력 계약은 절대 지우지 마세요.** 이 두 개가 "붙여 넣으면 도는 코드"와 "처음부터 다시 써야 하는 코드"를 가릅니다.

## 짧은 버전 (작은 작업용)

매번 전체 템플릿을 쓸 필요는 없습니다. 한 화면 안에 끝나는 작업은 이 정도면 충분합니다.

```text
[환경] (언어/버전), (실행 방식), (사용 가능 패키지)
[입력] (이름 : 타입 / 스키마 한 줄)
[출력] (이름 : 형태)
[요구] 1. … 2. … 3. …
[제약] (금지 사항), 빈 입력·결측·0나누기 방어
[요청] 전체 코드 + 한국어 주석 + 3줄 설명
```

실제로 채우면 이렇게 됩니다.

```text
[환경] Python 3.9, 사내 배치 서버, pandas/numpy 만 사용 가능(설치 불가)
[입력] df : DataFrame — ORDER_ID(str), CUST(str), ORDER_DT(str 'YYYY-MM-DD'), AMOUNT(float, 결측 있음)
[출력] result : DataFrame — CUST, MONTH, ORDER_CNT, AMOUNT_SUM
[요구] 1. ORDER_DT 를 날짜로 변환 2. 고객×월별 건수/금액 합계 3. 금액 결측은 0 이 아니라 제외하고 집계
[제약] inplace 금지, apply(axis=1) 금지, 빈 입력에서 죽지 않을 것
[요청] 전체 코드 + 한국어 주석 + 3줄 설명
```

## 환경 블록 스니펫 모음

`[환경]` + `[입출력 계약]` 만 갈아 끼우면 어디서든 같은 템플릿을 씁니다.
자주 쓰는 환경은 아래에서 골라 붙이세요.

### Spotfire Python 데이터 함수

```text
[환경] Spotfire Python 데이터 함수 (번들 인터프리터), pandas/numpy 사용 가능
[입출력 계약]
- 입력 input 은 이미 준비된 pandas DataFrame (파일 읽기 불필요)
- 결과는 output 변수에 DataFrame 으로 할당
- 파일 입출력·print 사용 불가, import 는 스크립트 안에 포함
```

### 일반 Python 스크립트

```text
[환경] Python 3.11, 로컬 실행, requirements 에 추가 가능 / 불가
[입출력 계약]
- 입력 : ./input/*.csv (UTF-8, 헤더 있음)
- 출력 : ./output/result.xlsx (시트명 'summary')
- 실행 : python run.py --date 2026-03-02 형태의 CLI 인자 지원
```

### SQL

```text
[환경] Oracle 19c (또는 PostgreSQL 15 / MS SQL 2019 / BigQuery)
[입출력 계약]
- 입력 테이블 : FAB_MEAS(약 1억 행, MEAS_TIME 파티션), LOT_MASTER(1만 행)
- 출력 : SELECT 문 하나로 결과 반환 (임시 테이블 생성 권한 없음)
- 제약 : 윈도우 함수 사용 가능, CTE 사용 가능, 힌트는 쓰지 말 것
```

### 엑셀 (VBA / 수식)

```text
[환경] Excel 365, VBA (매크로 사용 가능) / 또는 수식만 사용
[입출력 계약]
- 입력 : 'RAW' 시트 A1 부터 헤더 포함, 행 수는 매번 달라짐
- 출력 : 'SUMMARY' 시트에 결과 표를 A1 부터 작성 (기존 내용은 지우고 다시 쓰기)
- 제약 : 외부 참조·추가 설치 없이 동작해야 함
```

### 웹/프론트엔드

```text
[환경] TypeScript 5, React 18, 사내 디자인 시스템만 사용(외부 UI 라이브러리 추가 불가)
[입출력 계약]
- 입력 : props 로 data: Row[] 를 받음 (Row 타입 정의는 아래 참조)
- 출력 : 단일 컴포넌트를 export default
- 제약 : 상태 관리 라이브러리 추가 금지, fetch 는 상위에서 처리하므로 컴포넌트 안에서 호출 금지
```

{: .참고 }
> 사내 표준 환경이 정해져 있다면 **이 블록을 한 번만 잘 써서 팀 위키나 스니펫에 저장**해 두세요.
> 그 다음부터는 `[요구사항]` 만 바꾸면 됩니다. 이것이 개인 생산성 차이가 가장 크게 벌어지는 지점입니다.

## 상황별 변형

### ① 새로 만들 때

위의 전체 템플릿을 그대로 사용합니다.

### ② 기존 코드를 고칠 때

````text
[목표] 아래 코드에 (기능)을 추가하고 싶다.

[현재 코드]
```
(전체 코드. 일부만 붙이면 AI가 나머지를 지어냅니다)
```

[현재 동작] (지금은 무엇을 하고 있는지)
[바꿀 점]
1.
2.
[유지할 점] (건드리면 안 되는 부분·기존 출력 형식·함수 시그니처)

[요청]
- 바뀐 부분만이 아니라 전체 코드를 다시 주세요
- 무엇을 왜 바꿨는지 변경 요약을 함께 주세요
````

{: .주의 }
> **"바뀐 부분만 보여줘"라고 하면 붙여 넣다가 반드시 실수합니다.**
> 짧은 코드라면 항상 전체를 요구하세요. 긴 코드라면 반대로 "수정된 함수 전체"처럼 **경계가 분명한 단위**로 요구하세요.

### ③ 오류를 해결할 때

````text
[상황] 아래 코드를 실행하면 오류가 납니다.

[오류 메시지]
(전문을 그대로. 요약하지 말 것 — 마지막 줄만이 아니라 전체 트레이스백)

[코드]
```
(전체 코드)
```

[환경] (언어/버전, 라이브러리 버전, 실행 위치)
[데이터] (행 수, 컬럼, 관련 컬럼의 실제 값 예시 2~3개)
[시도한 것] (이미 해 본 것 — 같은 답을 다시 받지 않기 위해)

[요청]
1. 원인을 한 문장으로
2. 수정한 전체 코드
3. 같은 실수를 반복하지 않으려면 무엇을 알아야 하는지
````

### ④ 코드를 이해하고 싶을 때

```text
아래 코드를 한 줄씩 설명해줘. 나는 (파이썬 초급 / SQL 은 아는데 pandas 는 처음) 수준이야.
1. 전체가 무엇을 하는 코드인지 3줄 요약
2. 블록별로 무엇을 하는지
3. 이 코드가 조용히 틀릴 수 있는 상황이 있다면 어디인지
4. 내가 값을 바꿔 가며 실험해 볼 만한 부분은 어디인지
```

### ⑤ 검토를 시킬 때

````text
아래 코드가 의도대로 동작하는지 검토해줘.
[의도] (무엇을 하려는 코드인지)

```
(코드)
```

특히 아래 관점으로 봐줘:
1. 결측·빈 입력·중복이 있을 때 결과가 왜곡되는 지점
2. 0으로 나누기, 인덱스 범위, 타입 변환에서 깨질 수 있는 지점
3. 정렬이 필요한데 빠진 곳
4. 데이터가 100배 커졌을 때 느려질 지점
5. 이 코드를 처음 보는 사람이 오해할 만한 부분

문제가 없으면 '없음'이라고 말해줘. 있는 것처럼 지어내지 마.
````

{: .팁 }
> 마지막 한 줄(**"없으면 없다고 해줘"**)은 효과가 큽니다.
> 이 말이 없으면 AI는 성의를 보이려고 **사소한 것을 문제인 양 만들어 내는 경향**이 있습니다.

### ⑥ 성능을 개선할 때

````text
아래 코드가 (데이터 규모)에서 (현재 소요 시간) 걸립니다. (목표 시간) 이내로 줄이고 싶습니다.

```
(코드)
```

[조건] 결과는 완전히 동일해야 함 / 사용 가능한 것은 (라이브러리·메모리 한도)
[요청]
1. 병목이 어디인지, 왜 느린지
2. 개선한 전체 코드
3. 예상 개선 폭과, 결과가 같은지 확인하는 방법
````

### ⑦ 다른 언어·도구로 옮길 때

```text
아래 (SQL / VBA / R) 코드를 (Python pandas) 로 옮겨줘.

[원본 코드]
(코드)

[옮길 환경] (환경 블록)
[요청]
- 동작이 완전히 같아야 함. 다르게 동작할 수밖에 없는 부분이 있으면 먼저 알려줘
- 원본의 각 부분이 새 코드의 어디에 해당하는지 대응표
- 두 결과가 같은지 확인하는 방법
```

## 채워 넣은 예시

<div class="code-example" markdown="1">

**예시 1 — Spotfire 데이터 함수**

````text
[목표] 설비별 계측값의 관리 이탈을 매일 확인하고 싶다.

[환경] Spotfire Python 데이터 함수, pandas/numpy 만 사용
[입출력 계약] 입력 input(DataFrame), 결과는 output / output_report 에 할당.
파일 입출력·print 불가, import 는 스크립트 안에 포함.

[데이터] 약 11,000행
EQP_ID     문자열   'EQP-07'
STEP_DESC  문자열   'PC','RMG','CBCMP','ETCH','PHOTO'
MEAS_TIME  문자열   '2026-03-02 06:00:00'  ← 문자열이라 변환 필요
THICKNESS  실수     결측 있음
알려진 문제: 완전 중복 행 있음, MEAS_TIME 정렬 안 되어 있음

[요구사항]
1. 완전 중복 행 제거 후 MEAS_TIME 을 datetime 으로 변환
2. EQP_ID × STEP_DESC 별 평균·표준편차 계산
3. 평균에서 ±3σ 를 벗어난 행에 OUTLIER = 1 플래그
4. 결과 컬럼: EQP_ID, STEP_DESC, MEAS_TIME, THICKNESS, MEAN, STD, Z, OUTLIER

[제약]
````
