## 1. "Spotfire 데이터 함수"라고 명시한다

가장 효과가 큰 한 줄입니다. 이 말이 없으면 AI는 **독립 실행 스크립트**를 만듭니다.

```text
Spotfire Python 데이터 함수를 작성해줘.
입력은 이미 pandas DataFrame 변수로 준비되어 있고, 결과는 output 변수에 할당해야 해.
파일 읽기/쓰기와 print 는 사용할 수 없어.
```

## 2. 하지 말아야 할 것을 함께 적는다

"무엇을 해라"만큼 **"무엇을 하지 마라"** 가 중요합니다.
AI는 인터넷의 오래된 코드를 많이 학습했기 때문에, 명시하지 않으면 옛날 방식이 나옵니다.

```text
[제약]
- inplace=True 금지 (최신 pandas에서 동작하지 않음)
- apply(axis=1) 금지, 벡터 연산 사용
- 컬럼명을 하드코딩하지 말 것
- sklearn 없이 numpy 만으로 구현
- 전체 컬럼을 일괄 검사하는 방식(df != 0).all(axis=1) 사용 금지
```

## 3. 요구사항에 번호를 매긴다

```text
1. THICKNESS 결측 행 제거
2. EQP_ID 별 평균/표준편차 계산
3. 평균에서 3시그마 벗어난 행에 OUTLIER 플래그
```

번호를 매기면 **누락이 눈에 보이고**, 나중에 "3번만 다시 해줘"라고 요청할 수 있습니다.

## 4. 판정 기준을 숫자와 문장으로 명시한다

애매한 표현은 AI가 마음대로 해석합니다.

| ❌ 애매함 | ✅ 명확함 |
|---|---|
| "이상치를 찾아줘" | "IQR 기준 Q1-1.5×IQR 미만 또는 Q3+1.5×IQR 초과를 이상치로 표시" |
| "최근 데이터만" | "MEAS_TIME 기준 최근 7일" |
| "그룹별로 정리" | "EQP_ID와 STEP_DESC 조합별로 집계, 결과 행은 그룹당 1행" |
| "관리도 룰 적용" | "Rule2: 연속 9점이 중심선 같은 쪽에 있으면 위반" |

{: .팁 }
> **통계 용어·표준 규격 이름은 그 자체로 훌륭한 사양입니다.**
> "Western Electric Rule", "Cpk", "Welch t-test", "Bonferroni 보정", "merge_asof", "Hampel filter" —
> 이런 이름을 알고 있으면 프롬프트가 짧아지고 정확해집니다.
> **AI 시대에 용어를 아는 것의 가치가 오히려 커졌습니다.**

## 5. 출력 형태를 먼저 그린다

원하는 결과 테이블의 **컬럼 목록**을 직접 적어 주세요.

```text
결과 컬럼: EQP_ID, STEP_DESC, N, MEAN, STD, CPK, JUDGE
JUDGE 는 CPK>=1.33 '양호', 1.0 이상 '관리필요', 그 외 '개선필요'
```

이렇게 하면 결과를 받자마자 맞는지 **눈으로 확인**할 수 있습니다.

## 6. 예시 데이터를 붙인다 (특히 문자열 처리)

정규식·날짜 파싱·코드값 정리에서는 **실제 문자열 2~3개**가 설명 열 줄보다 낫습니다.

```text
MESSAGE 컬럼 예시:
  [E-1023] Chamber pressure high (LOT=L26043, STEP=ETCH, value=12.34 unit)
  [W-3305] Slurry flow low (LOT=L26101, STEP=CBCMP, value=3.7 unit)
여기서 알람코드, LOT, STEP, value 를 각각 컬럼으로 추출해줘.
```

## 7. 빈 결과·결측·0으로 나누기 방어를 요구한다

데이터 함수가 운영 중에 죽는 이유는 대부분 **예외 상황**입니다.

```text
아래 상황에서 오류 없이 동작하게 해줘:
- 입력이 0행인 경우 (마킹이 비어 있을 때)
- 특정 그룹의 표준편차가 0인 경우
- 결과가 0행인 경우 → 안내 문구가 든 1행 테이블 반환
- 지정한 컬럼이 없는 경우 → 명확한 오류 메시지
```

## 8. 검증 코드를 함께 요청한다

```text
처리 결과가 맞는지 확인할 수 있도록,
처리 전후 행 수·컬럼별 결측 수·제거 건수를 요약한 output_report 도 만들어줘.
```

리포트 테이블 하나가 **결과 신뢰도를 완전히 바꿉니다.**
현업 리뷰에서 "이거 맞아요?"라는 질문에 화면으로 바로 답할 수 있습니다.

## 9. 주석과 설명을 요구한다

```text
코드에 한국어 주석을 달아주고,
각 단계가 무엇을 하는지 코드 아래에 3~5줄로 요약해줘.
왜 그 방법을 선택했는지도 한 줄씩 설명해줘.
```

**설명을 요구하면 코드 품질 자체가 올라가고**, 여러분이 검증할 수 있게 됩니다.
이해 못 한 코드는 운영에 올리지 마세요.

## 10. 한 번에 다 시키지 말고 나눠서 쌓는다

```text
(1차) 먼저 데이터를 정제하는 부분만 만들어줘.
(2차) 좋아. 여기에 EQP_ID 별 관리한계선 계산을 추가해줘.
(3차) 이제 Western Electric Rule 1과 2를 추가해줘.
```

한 번에 요구사항 10개를 던지면 일부가 조용히 누락됩니다.
**단계별로 확인하며 쌓는 방식**이 훨씬 안전하고 빠릅니다.

## 11. 실패했을 때는 증상을 그대로 붙인다

"안 돼요"라고만 하면 AI는 추측합니다. **오류 메시지 전문 + 코드 + 데이터 정보**를 주세요.

````text
아래 코드에서 오류가 납니다.

[오류]
ValueError: left keys must be sorted

[코드]
```python
(전체 코드)
```

[데이터]
input1.shape = (11091, 15), input2.shape = (1344, 22)
input1 은 MEAS_TIME 으로 정렬되어 있지 않습니다.

원인과 수정된 전체 코드를 알려주세요.
````

## 12. 대안을 물어본다

```text
이 방법 말고 다른 접근이 있으면 2~3가지 제시하고,
각각의 장단점과 어떤 상황에 적합한지 비교해줘.
데이터가 100만 행일 때 가장 빠른 방법은 뭐야?
```

특히 **성능**이 중요한 경우, AI에게 대안을 물으면 훨씬 나은 코드를 얻는 경우가 많습니다.
